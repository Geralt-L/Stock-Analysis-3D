# 投研笔记 Skill

把对话中的投研分析固化为可回溯、可复盘的笔记体系。核心价值不是"存文件"，而是**强制结构化（一句话结论 + 验证点 + 失效条件）和定期复盘（结论要么兑现要么作废，不许烂尾）**。

## 目录约定

```
notes/
├── INDEX.md          # 索引（倒序表格），每次增删笔记必须同步更新
├── TEMPLATE.md       # 笔记模板，新建笔记从这里复制结构
└── YYYY-MM-DD_主题.md  # 笔记正文，统一命名
```

## 命名规范（硬性）

- 格式：`YYYY-MM-DD_主题.md`，主题用简短中文、下划线连接多个关键词，如 `2026-07-18_存储专题_澜起联芸与港股通标的.md`
- 日期 = 分析基准日（数据截止日），不是写作日
- 同日多篇：在主题上区分，不加数字序号
- 禁止空格，禁止无日期文件名

## 工作流 A：新建笔记

```
[STEP 1] Read notes/INDEX.md → 检查历史笔记有无到期验证点（见工作流 B），有则先提示用户
[STEP 2] Read notes/TEMPLATE.md → 按模板生成笔记
         内容来源：本次对话中的分析结论；数字必须是对话中检索过的真实数据，缺失就重新 WebSearch，不许编造
[STEP 3] 写入 notes/YYYY-MM-DD_主题.md
[STEP 4] 更新 notes/INDEX.md：表格顶部插入一行（日期|主题链接|一句话结论|关键验证点|状态🔍|备注）
[STEP 5] git add notes/ && git commit -m "notes: YYYY-MM-DD 主题" && git push
         （在 PR 工作流中推到当前工作分支；独立使用时推 main）
[STEP 6] 回复用户：笔记路径 + 一句话结论 + 下一个验证点日期
```

## 工作流 B：复盘（用户说「复盘」，或 STEP 1 发现验证点到期时）

```
[STEP 1] Read notes/INDEX.md，找出状态为 🔍 且验证点日期已过的笔记
[STEP 2] 对每篇：WebSearch 核实验证点结果（财报是否兑现、点位是否守住、价格是否转向）
[STEP 3] 更新笔记文末验证点复选框 + INDEX.md 状态列：
         ✔️ 已验证（结论兑现）/ ⛔ 已失效（失效条件触发）/ 🔍 继续等待
         在 INDEX.md 备注列写一句结果（如「Alphabet capex 上调，判决通过」）
[STEP 4] 若结论失效：在原笔记文末追加「## 复盘更正」小节说明错在哪，不删除原文——错误记录是笔记体系最有价值的部分
[STEP 5] commit + push，向用户汇报复盘结果
```

## 笔记必含要素（缺一不发）

1. **一句话结论**（加粗，"怎么看 + 怎么做"）
2. **数据截止时间**（盘中快照 / 收盘定稿）
3. **可买域标注**：涉及标的必须标注上市板块；用户只能买 **沪深主板（60/000/001/002/003 开头）+ 港股通**，创业板（300/301）/科创板（688）标的必须显式标注「不可买，仅研究」
4. **区分归母与扣非**：业绩增速必须写清口径，非经常性损益占比大时必须点破
5. **估值四大陷阱自查**（见 TEMPLATE.md）：周期顶利润做分母 / 增长注水 / 曲棍球杆预测 / 相对便宜≠低估
6. **验证点 + 失效条件**：没有可证伪条件的结论不许写
7. **免责声明**：仅供研究参考，不构成投资建议

## 硬性规则

- 所有价格、估值、业绩数字来自真实检索，标注来源；宁缺毋造
- 一篇笔记只服务一个主题，大而全的拆成多篇
- INDEX.md 是唯一入口，任何笔记操作必须同步更新索引
- 复盘发现结论错误时只追加更正、不删改原文
- 用户口头分析请求默认不落盘；只有触发场景命中时才写文件
